## 怎样证明测试不是单核串行运行

使用 `kernel_thread_on_cpu()` 在唤醒前完成绑核，每一轮检查实际 CPU 编号。
两个线程都完成分配、发布指针后，才开始校验与释放；两个线程都释放完，
才进入下一轮。使用原子 release/acquire 同步，而不是依靠普通变量或 volatile。

校验内容：

- 两个 CPU 同时持有的全部对象地址不得重复。
- 每个对象头尾各 32 B 写入 CPU、轮数和槽位相关的 pattern，释放前验证；
  64 B 对象覆盖全部内容，较大对象不是全内容检查。
- 每组分配次数必须与命中数 + 未命中数一致；Buddy 另检查每 CPU 计数和 refill 归属。
- 排空专用 Slab cache 后，剩余 Slab 页为零；全局 Buddy + PCP 空闲页恢复。
- 等待交接超过 10 秒触发 panic，而不是无限等待；退出时回收两个测试线程。

这验证的是指定工作负载，不等于所有并发错误都已排除。尚未覆盖：长期随机混合
分配、内存耗尽、IRQ 重入、CPU 热插拔、迁移压力、多种高阶页并发分配和实际 ARM 板。

## 参数和统计口径

| 参数组 cfg | PCP high / batch（页） | Slab limit / batch（对象） |
| --- | --- | --- |
| 0 | 16 / 4 | 4 / 2 |
| 1 | 32 / 8 | 8 / 4 |
| 2 | 64 / 16 | 16 / 8 |

测 Slab 时，PCP 固定为 32 / 8，避免同时改变上下两层参数。
每组开始排空 PCP 与测试专用 Slab cache，计时阶段不打印日志。

- `kind=0/1/2`：Buddy 单页 / Slab 64 B / Slab 1 KiB。
- `mode=0/1/2`：每核 8 个本核释放 / 每核 64 个本核释放 / 每核 64 个跨核释放。
- 命中率 = 本地缓存直接命中次数 / 分配次数。未命中并不表示分配失败。
- PCP 的 `global` 是成功 refill + drain 的批次数；Slab 的 `global` 是
  refill/drain 中获取 cache 全局锁的次数，包含新增 Slab 的挂链操作。
  二者不是同一种计数，也不等于单纯的分配未命中次数。
- 一“对”表示一次分配和对应的一次释放；两个 CPU 的计数相加。
- 耗时取两个工作线程中较长者，包含校验、交接等待和调度，
  不包含测试前调参以及测试后显式排空。它是压力负载吞吐，不是纯分配器调用吞吐。
- 下表每行汇总三次重复；吞吐按总对数 / 总耗时计算，不直接平均各轮吞吐率。
- 清理前占页：Buddy 为两个 PCP 的空闲页；Slab 为专用 cache 尚占用的页，
  包含缓存对象所在的整页，不包含 Slab 下层 PCP，也不包含 cache 描述符。
  波动来自并发执行顺序；这些空闲缓存不是泄漏。

## 调参选择

1. PCP 默认从 **32 / 8 改为 64 / 16**。64 页跨核释放负载中，
   命中率从 93.70% 提高到 99.95%，每组全局批次从 2,056 降到 8，
   压力吞吐提高约 **24.2%**。
   代价是这组负载双核的 PCP 占用从 256 KiB 增到 512 KiB。
   8 页负载的收益很小，不能说所有场景都更快。
2. Slab 保留原有 **16 / 8**，但现在有了与 4 / 2、8 / 4 的对比依据。
   64 个对象跨核释放负载中，相比 8 / 4，64 B 对象的吞吐提高约
   **18.5%**，1 KiB 对象提高约 **9.4%**。
   这是候选参数间的差异，**不是相对修改前默认 Slab 的性能提升**。
   较大对象的缓存占页更多，需要继续结合真实工作负载取舍。

本轮只是在所测参数和负载中选取折中，不声称找到了通用最优值。
PCP 中的页需要 drain 才能参与 Buddy 合并；这里没有增加内存压力下自动回收
所有 CPU 缓存的机制，高阶分配和低内存场景仍需单独评估。

## 本次补齐的代码

- 修正 PCP refill 统计误写到 CPU 0 的问题。
- 在选择当前 CPU 的 PCP / magazine 之前禁止抢占，完成操作后恢复，
  避免“取得 CPU 编号后被迁移”的窗口；临界区仍使用原来的锁。
- 增加 PCP 快照/调参、Slab 缓存容量/批量参数及全局路径计数。
- 提供显式 Slab 排空：同时清理 magazine 和并发 refill 可能额外产生的空 Slab；
  向 Buddy 归还页面仍在 cache 全局锁之外。
- 测试专用 cache 在无并发使用时调参、排空和释放，不改变普通 kmalloc cache。
- 调度算法本身沿用现有 per-CPU RunQueue / 优先级 RR，本轮不是完整的调度公平性测试。

## 复现和安全范围

配置开启 `CONFIG_TEST_MM_SMP = y`，设备树启用 cpu1，并使用
`-smp 2 -accel tcg,thread=multi`。具体入口见
[测试说明](../README.md#多核内存分配测试)。
本次使用临时配置、临时双核 DTB 和原磁盘镜像的副本，更新的是副本启动分区，
没有写原镜像。最终已恢复默认配置构建，压力测试默认不开启；
另用单核 QEMU 验证默认构建可以正常启动到用户态 Shell。

实验 QEMU 参数（路径替换为自己的测试副本，禁止把临时修改写回日常镜像）：

```sh
qemu-system-riscv64 -accel tcg,thread=multi -smp 2 -m 256M \
  -machine virt -bios default -cpu rv64,sstc=on \
  -kernel tools/bootloaders/qemu-riscv64/u-boot.bin \
  -drive file=/tmp/your-test/disk.img,if=none,format=raw,id=disk0 \
  -device virtio-blk-device,drive=disk0,bus=virtio-mmio-bus.0 \
  -global virtio-mmio.force-legacy=false -nographic
```

需要将启用测试后生成的 uImage 及双核 DTB 安装到这个副本的启动分区，
仅替换 QEMU 的 -smp 参数不会替换内核或设备树。
