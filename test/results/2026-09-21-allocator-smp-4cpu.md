跨核模式使用环形交接：CPU0 释放 CPU1 分配的对象，CPU1 释放 CPU2 的对象，
CPU2 释放 CPU3 的对象，CPU3 释放 CPU0 的对象。开始释放前，四个 CPU 都必须
完成本轮分配；进入下一轮前，四个 CPU 都必须完成释放。

地址唯一性会跨全部四个 CPU 的同时存活对象检查。对象头尾 pattern、每 CPU
分配统计、Slab 排空、Buddy + PCP 空闲页恢复等校验与双核测试相同。

在四核、每核每轮 64 个对象的跨核负载中：

- PCP 64/16 相比 32/8，压力吞吐提高约 **19.9%**，全局批次从
  4,112 降至 16；代价是四核 PCP 最多保留 1 MiB，而 32/8 保留 512 KiB。
- Slab 16/8 相比 8/4，64 B 对象吞吐提高约 **13.6%**，
  1 KiB 对象提高约 **12.3%**。Slab 的 global 是取得 cache 全局锁
  的诊断计数，和 PCP 的批次数不是同一口径。

吞吐包含对象校验、四核屏障、调度和分配/释放，不是纯 allocator API 性能；
TCG 的 CPU 调度也不能等价于真实四核硬件，因此适合比较同一环境下的参数，
不适合宣称裸机绝对性能或线性扩展。

## 四核运行带来的额外修正

测试从固定两个线程改为自动使用 2～4 个连续在线 CPU，并把两两交换改为环形交接。
同时发现 `set_cpu_online()` 原来使用普通的 `cpu_online_map |= bit`，多个辅助核
并发上线时存在丢失其他 CPU 位的读改写竞争；现改为原子 fetch-or，并用 acquire
读取在线位图。

本测试覆盖指定分配负载，仍不等价于证明任意多核并发、IRQ 重入、内存耗尽、
CPU 热插拔或真实硬件缓存一致性都正确。
