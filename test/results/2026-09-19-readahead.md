# Page Cache 顺序预读测试

由 OpenAI Codex 实现并记录，2026-09-19。

## 实现范围

- 每个打开的文件独立记录上次访问页和窗口大小；从文件头开始读取，或访问
  同一页/相邻下一页时允许预读。窗口在缺页时按 4、8、16 页增长。
- 最大窗口 64 KiB，包含当前必需页；随机跳转时先恢复为按需读取。
- Page Cache 先持有整批页面引用，再加页锁；已经有效或脏的页不交给批量读取。
- Ext2 将磁盘扇区连续的数据组成多页 BIO；遇到空洞或磁盘不连续时拆分，
  单个 BIO 最多 16 个 vec。完成后才将整批成功页标记为有效。
- 预读分配不足时缩小本次批次，批量读取失败时回退当前必需页。
- 修复 Ext2 读请求跨 EOF 时的范围裁剪，部分成功后返回已经读取的字节数。

当前为同步批量预读，收益来自请求合并及之后的缓存命中；尚未实现后台异步预读。
沿用现有 Page Cache/LRU 的并发约束，本次只验证单核，不代表多核缓存访问已安全。

## 测试条件

| 项目 | 值 |
| --- | --- |
| 平台 | QEMU RISC-V64 virt，1 CPU，命令行内存 256 MiB |
| 数据页大小 | 4 KiB |
| 文件 | `/bin/ls`，1,031,696 字节，约 1007.52 KiB |
| 轮次 | 每种请求大小，开启/关闭各 3 轮，交替执行 |
| 冷缓存含义 | 每轮失效该文件的 Page Cache 数据页 |
| 其他缓存 | 宿主机磁盘缓存、Ext2 间接块缓存已预热 |
| 耗时范围 | 文件读取和逐字节校验和计算 |
| 测试磁盘 | `/tmp/zzz-readahead.1xKk03/disk.img`，原镜像副本 |
| 原始日志 | `/tmp/zzz-readahead.1xKk03/final.log`（临时文件） |

## 实测结果

| 读取请求大小 | 关闭预读平均耗时 | 开启预读平均耗时 | 耗时下降 | 关闭吞吐 | 开启吞吐 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 512 B | 48.773 ms | 33.386 ms | 31.5% | 20.17 MiB/s | 29.47 MiB/s |
| 4 KiB | 41.685 ms | 27.001 ms | 35.2% | 23.60 MiB/s | 36.44 MiB/s |
| 64 KiB | 43.770 ms | 25.971 ms | 40.7% | 22.48 MiB/s | 37.88 MiB/s |

每组校验和均为 `e9e447d5a6074d7f`。以上是同一内核中关闭/开启预读的对照，
不是与历史的 42% 改善相加，也不是物理磁盘冷启动性能。

## 正确性检查

| 检查 | 结果 |
| --- | --- |
| 原有文件读取测试 | PASS：14,274 个用例，校验 7,871,729 字节 |
| 首次读取 1 字节后预读 4 页 | PASS，4 页均有效 |
| 跳转至第 20 页 | PASS，只增加必需页，窗口重置 |
| 文件尾剩余 32 字节时请求 64 KiB | PASS，返回 32，剩余缓冲区哨兵未改变 |
| 零长度、EOF、越过 EOF | PASS，返回 0 |
| 批量回调注入 EIO | PASS，当前页回退成功，其他页未误标有效 |
| 模拟读取 601 页（超过 256 页缓存容量） | PASS，逐字节校验，窗口增长至 16 页 |
| 单核启动进入用户态 shell | PASS |

错误注入与回收压力使用模拟 address_space 回调，未模拟真实 VirtIO 故障。
真实稀疏文件、不同 Ext2 块大小、并发读写和分配失败注入尚未做专项测试。

## 复现

在单核测试配置中启用 `CONFIG_TEST_FS_READ = y` 和
`CONFIG_TEST_READAHEAD = y`，构建内核并部署到测试镜像。
启动时观察 `fs-read-test: PASS` 和 `readahead-test: PASS`。
每种请求的原始 `avg_us`、`KiB_s` 和校验和由测试直接打印。
